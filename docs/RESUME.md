# 简历项目描述（可直接粘贴）

---

**项目名称：** diet-agent —— 多 Agent 对话式智能饮食推荐系统

**项目简介：**

面向"不知道吃什么"的日常就餐决策难题，打造基于多 Agent 协作的对话式智能饮食推荐系统。用户用自然语言表达就餐需求（如"今晚想吃清淡点的"），系统自动完成意图识别、槽位澄清、餐食检索重排、LLM 推荐理由生成，输出带推荐理由的餐食卡片；同时支持个人/公共双数据源、多餐规划、"换一批"调整推荐等能力。项目采用"编排中枢 + 专职 Worker"的多 Agent 架构，LLM 仅负责结构化推理输出，会话流转与状态维护由编排层统一管控；并配套全链路 Trace 可观测与离线批量评估体系，支撑线上问题排查与指标驱动的持续迭代。

**技术栈：**

Java 21 / Spring Boot 3.3 / MyBatis / MySQL 8（JSON_OVERLAPS 标签检索）/ AgentScope（ReActAgent）/ 阿里云百炼 DashScope（Qwen-Max、Qwen-Turbo）/ 原生 JS 单页应用

**核心设计：**

1. **多 Agent 编排架构**：将链路拆分为意图识别、槽位澄清、推荐生成、多餐规划 4 个专职 Agent，由 DietOrchestratorService 作为编排中枢统一管控会话状态与路由；Agent 只输出结构化 JSON、不直接读写业务状态，实现"LLM 推理"与"业务流转"解耦，状态可测试、链路可回放。

2. **检索重排在 LLM 之前（防幻觉）**：采用"MySQL 标签召回（JSON_OVERLAPS）→ Java 规则打分重排（7 维槽位重叠率）→ LLM 生成推荐理由"的两段式架构。候选餐食与 mealId 由规则层确定，LLM 只做语言表达且 prompt 强制禁止编造候选，从源头治理 LLM 幻觉。

3. **全链路 Trace 可观测**：基于 ThreadLocal + 事件模型，在一轮请求的关键节点（意图识别、槽位合并、检索重排、Agent 调用、守卫检查等）记录输入/输出/耗时/Token 等 Trace 事件并落库，支持按 traceId/sessionId 逐步回放，线上问题可定位到具体环节。

4. **离线评估闭环**：批量解析 Trace 事件，融合"规则指标（意图准确率、Token 成本、端到端耗时、幻觉控制等 10+ 项）+ LLM Judge 质量分 + 用户反馈"三方评分（60/10/30 加权）输出百分制报告；低分样本经人工标注回流，形成"Trace 标注 → 批量评估 → 指标驱动迭代"的工程闭环。
